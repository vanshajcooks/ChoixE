Slide 02 of 14 • Business Context & Motivation Problem Statement & Enterprise Need

Transforming fragmented institutional campus recruitment into a governed enterprise workflow
Challenges in Traditional Placement Drives
  • Data Fragmentation: Student details and academic records scattered across spreadsheets, Google Forms, and informal chats.
  • Manual Eligibility Auditing: Placement coordinators manually cross-check CGPA, active backlogs, and branch criteria for hundreds of applicants.
  • Lack of Traceable Audits: Application status changes lack timestamped historical logs, leading to disputes and communication loss.
  • Uncoordinated Scheduling: Students miss interview slots due to fragmented broadcast channels and delayed recruiter feedback.
  • Security & Privacy Vulnerabilities: Academic records and resumes shared openly without access controls or role isolation.
Enterprise Value Proposition
  • Unified 3-Tier Ecosystem: Centralized portal connecting Students, Corporate Recruiters, and the College Placement Cell (TPO).
  • Automated Eligibility Engine: Server-side rule engine verifies CGPA, department, and backlog criteria before application submission.
  • Mandatory Governance: TPO verifies student profiles and approves company job postings before campus-wide visibility.
  • Auditable State Machine: Every application transition is validated and permanently logged with reviewer remarks.
  • Institutional Intelligence: Real-time analytics for placement percentages, average salary packages, and branch metrics.
Screenshot & Demo Guidance: Showcase comparison between unstructured student spreadsheets and the clean, unified CampusConnect dashboard.
Speaker Notes: "Campus placement drives handle hundreds of companies and thousands of applications. The manual approach fails when verifying complex criteria across branches. CampusConnect solves this at the enterprise level by shifting compliance, verification, and scheduling to an automated backend."

Slide 05 of 14 • Security Architecture Role-Based Access Control (RBAC) & Authorization

Multi-tenant role boundaries enforced at URL, controller, and service layers
Security Principles Enforced
  • Least Privilege: Strict endpoint restriction via Spring Security URL antMatchers.
  • Role Mapping: Authenticated sessions mapped to ROLE_STUDENT, ROLE_RECRUITER, or ROLE_OFFICER.
  • Tenant Isolation: Recruiters cannot query or update other companies' candidates (prevents IDOR).
  • Dual Verification: Both presentation tags and service-layer assertions guard protected operations.

Slide 06 of 14 • Business Logic & Lifecycle Core Business Workflows & State Transitions

Finite State Machine ensuring validated, auditable application progression
Application State Machine Rules
  • Linear State Progression: Strict lifecycle: APPLIED → SHORTLISTED → INTERVIEW_SCHEDULED → SELECTED / REJECTED.
  • Transition Validation: Recruiter cannot jump straight to Selected without shortlisting and scheduling interviews.
  • Audit Trail Logging: Every status change records previous status, new status, reviewer ID, timestamp, and comments in ApplicationStatusHistory.
  • Two-Tier Job Approval: Company jobs remain in DRAFT / PENDING_APPROVAL until the TPO verifies job legitimacy.

Speaker Notes: "Notice the state machine governing applications. An enterprise application must protect against invalid states. If a recruiter attempts to schedule an interview for a rejected candidate or jump straight to selected, the service throws an ApplicationStatusTransitionException."

Slide 07 of 14 • Business Rules & Automation Automated Eligibility Evaluation Engine

Dynamic rule verification removing human error from candidate screening
Eligibility Criteria Parameters
  • Verification Status: Student profile must be explicitly approved (VERIFIED) by the TPO.
  • Graduation Year / Batch: Student passing batch must strictly match the target job batch (e.g., 2026).
  • Department Matching: Student department must be included in the company's allowed branch list.
  • CGPA / Score Threshold: Student CGPA must be greater than or equal to the minimum required CGPA.
  • Active Backlogs Limit: Current active backlogs must not exceed the job's maximum allowed limit.
  • Deadline Enforcement: Submission timestamp must precede the application deadline.
Evaluation Pipeline Architecture
  • Double-Gate Defense: Client-side badges inform the student, but the server executes an authoritative pre-save check.
  • Granular Diagnosis: Ineligible candidates receive explicit feedback explaining unmet conditions (e.g., 'CGPA 7.10 is below required 7.50').
  • Concurrency Protection: Relational database unique constraints prevent duplicate submissions on double-clicks.

Slide 08 of 14 • Database & Persistence Design Relational Data Model & Audit Architecture

Third Normal Form (3NF) relational design with entity relationships and audit logs
Schema Integrity & Relationships
  • User Entity Separation: Authentication credentials stored in User table; decoupled from StudentProfile and Company.
  • Job & Criteria Mapping: Job entity maintains a 1:1 relationship with JobEligibilityCriteria for clean rule isolation.
  • Composite Uniqueness: Unique constraint on (job_id, student_id) guarantees no duplicate applications.
  • Audit Logging: ApplicationStatusHistory preserves complete chronological records for academic compliance.
  • Cascade Management: Orphan removal and foreign keys prevent dangling interview or application records.

Slide 09 of 14 • Enterprise Non-Functional Attributes Enterprise Security, Transactions & Reliability

Defensive programming adhering to OWASP enterprise web security standards
Application Security Hardening
  • BCrypt Password Hashing: Passwords salted and hashed with adaptive work factor 10. No plaintext credentials stored.
  • CSRF Protection: Synchronizer Token Pattern enforced on all state-altering requests (POST/PUT/DELETE).
  • SQL Injection Immunity: Zero raw string concatenation; all database operations use Spring Data JPA parameterized queries.
  • XSS Defense: Server-side template engine (Thymeleaf) automatically escapes HTML characters on display.
  • IDOR Defense: Recruiter controllers enforce session ownership checks on requested student applicant IDs.
Transaction & Storage Integrity
  • ACID Compliance: Service operations decorated with @Transactional guarantee atomic rollbacks on exceptions.
  • State Concurrency: Prevents race conditions during simultaneous application status updates.
  • Secure File Storage: Student resumes stored with randomized UUID filenames outside public web directories to stop traversal attacks.
Screenshot & Demo Guidance: Visual Guide: OWASP Top 10 compliance badges (BCrypt Encryption, CSRF Token, JPA Parameterization, Transaction Rollback).
Speaker Notes: "Security and data integrity are central to Enterprise Web Applications. We have incorporated OWASP top 10 defenses: BCrypt hashing, CSRF token validation on every form submission, automated XSS escaping via Thymeleaf, and transactional rollbacks on service exceptions."
